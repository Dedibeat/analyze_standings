Setsuna is studying music theory. There are n distinct pitches, numbered 1, 2, · · · , n. Setsuna wants to
compose a melody P in which every pitch appears exactly once. We call a sub-melody Q compact if and
only if there exist integers l ≤ r such that the set of pitches appearing in Q is exactly {l, l + 1, · · · , r}.
To compose the harmony, Setsuna specifies some requirements using two strings a, b, each of length n:
• For the sub-melody P [1, i] consisting of the first i pitches:
– If ai = 1, this sub-melody must be compact.
– If ai = 0, this sub-melody must not be compact.
– If ai = ?, there is no restriction on this sub-melody.
• For the sub-melody P [i, n] consisting of the last n + 1 − i pitches:
– If bi = 1, this sub-melody must be compact.

After solving Don’t Fight The Music, Setsuna wants to enumerate all melodies that satisfy the
requirements. You need to help Setsuna find the number of such melodies so that she can check her
result. Since the answer may be large, output it modulo 998244353.

Input

For each test case:
• The first line contains an integer n (2 ≤ n ≤ 2 × 105 ).
• The next two lines each contain a string of length n, namely a and b.
It is guaranteed that the sum of n over all test cases does not exceed 2 × 105 , and that the strings contain
only the characters 1, 0, and ?.

Output

Hikari has collected n glass shards, numbered from 1 to n. Each shard has 64 binary attributes. The k-th
bit describes the k-th attribute, so the attribute value of a shard is an integer in [0, 264 ).
Then, m events happen to the “world”. Each event is one of the following:
1. A fracture of the first type has its own attribute value x and affects every shard whose index is

transformed into a shard with attribute value x.
2. Hikari needs to deal with the shards whose indices are in [l, r]. You need to tell her the sum of their
attribute values.
3. A fracture of the second type has its own attribute value x and affects every shard whose index is

Input

the first type.
• If opt = 2, two more integers l, r follow (1 ≤ l ≤ r ≤ n), describing a query from Hikari; since the
answer is large, you have to output it modulo 264 .
• If opt = 3, three more integers l, r, x follow (1 ≤ l ≤ r ≤ n, 0 ≤ x < 264 ), describing a fracture of
the second type.
It is guaranteed that at least one event has opt = 2.

Output
For each query from Hikari, output one line containing an integer representing the sum of the attribute
values modulo 264 .

Ras and Salt are playing a simplified version of Texas Hold’em called CAFE MiLK Poker. The game uses
2n cards with ranks 1 ∼ 2n, and proceeds as follows:
• One chip is placed in the center of the table. Each player has m chips and n cards.
• Ras and Salt each draw one card uniformly at random from their own deck.
• Both players know the two complete decks and the card they drew, but neither knows the card
drawn by the other player.
• Ras may choose to check or go all-in.
• If Ras checks, both players reveal their cards, and the player with the higher card takes the chip
on the table.
• If Ras goes all-in:
– Salt may choose to fold or call.
– If Salt folds, Ras takes the chip on the table.
– If Salt calls, both players reveal their cards, and the player with the higher card takes a total
of m + 1 chips from the table and the other player.
Ras and Salt may each use a mixed strategy π = pi : whenever the player makes a decision while holding
card i, they choose one action with probability pi and the other action with probability (1 − pi ). Both
players want to maximize their own expected profit, defined as the number of chips they have at the
end of the game minus m.
You are Chiffon, Ras’s best friend, and you know that Salt can read minds: although she cannot know
which card Ras drew, she can know Ras’s strategy! Therefore, you need to help Ras find a strategy that
maximizes her expected profit. Formally, you need to choose a mixed strategy πr for Ras that maximizes
Ras’s expected profit when Salt may choose her strategy πs based on πr .

Input
This problem contains multiple test cases.
The first line contains a positive integer T (1 ≤ T ≤ 104 ), representing the number of test cases.
For each test case:
• The first line contains two integers n, m (1 ≤ n ≤ 2 × 105 , 1 ≤ m ≤ 109 ).
• The second line contains n integers ai (1 ≤ ai ≤ 2n), representing Ras’s cards.
• The third line contains n integers bi (1 ≤ bi ≤ 2n), representing Salt’s cards.
It is guaranteed that the sum of n over all test cases does not exceed 2 × 105 , and that all ai and bi are
pairwise distinct; in other words, every integer from 1 through 2n occurs exactly once.

Output
For each test case, output one line containing a floating-point number representing the answer.
Your answer is considered correct if its absolute or relative error does not exceed 10−6 . Formally, let your
|a−b|
answer be a and the correct answer be b. Your answer is accepted if and only if max(1,|b|)
≤ 10−6 .

• You are given an undirected simple graph G with n vertices and m edges. The vertices are numbered
from 1 to n.
• A permutation p = [p1 , p2 , · · · , pn ] of 1, 2, · · · , n is a valid labeling of the graph if and only if
pu + pv ≤ n + 1 for every edge (u, v).
• It is guaranteed that at least one valid labeling exists. You need to find any valid labeling of the
given graph.
In the year 6202, Teto not only invented an eﬀicient algorithm for this problem with the help of a quantum
computer, but also invented a time machine! Now, Teto wants to bring a solution to this problem back
in time and accelerate the research into the algorithm. However, she finds that she cannot remember too
much information: besides remembering the graph exactly, she can remember only 5 × 105 additional
bits. Can you help her compress the information in the solution?
More specifically, you need to design a program that, given G and p, can generate a non-empty binary
string s of length at most 5 × 105 , and can then independently find a valid labeling p′ using only G and
s. Note that p′ only needs to be a valid labeling of the graph and does not have to be identical to p.
To test your program, the judging system will run the same program twice on each test, corresponding
to the two processes described above. The two runs do not share memory, files, or any other state. Apart
from the same graph and the binary string output on the first run, the second run receives no information
from the first run.

Input
The first line of each run contains a string op (op ∈ {first, second}), denoting which run of the program
it is.
The second line contains two integers n and m (2 ≤ n ≤ 105 , 0 ≤ m ≤ 5 × 105 ), denoting the number of
vertices and the number of edges, respectively. It is guaranteed that n is even.
The next m lines follow. The i-th of these lines contains two integers ui , vi (1 ≤ ui < vi ≤ n), denoting
an edge connecting vertices ui and vi .
If op = first, the last line contains n integers p1 , p2 , · · · , pn , representing a valid labeling given to the
program.
If op = second, the last line contains a non-empty binary string s, representing the information output
on the first run. It is guaranteed that the graph and the order of its edges are identical in both
runs.
It is guaranteed that all edges in the graph are distinct. If op = first, it is also guaranteed that p is a
permutation of 1, 2, · · · , n and that pu + pv ≤ n + 1 for every edge (u, v).

Interaction Protocol
If op = first, output a non-empty string s consisting only of the characters 0 and 1, where |s| ≤ 5×105 .
Do not output anything else.
If op = second, output a permutation p′1 , p′2 , · · · , p′n of 1, 2, · · · , n such that p′u + p′v ≤ n + 1 for every
edge (u, v).

This is an interactive problem.
Having awakened, Ivy is exploring the road network of Node 08.
Node 08 can be modeled as an n-vertex edge cactus, and Ivy needs to find every edge in the graph.
Fortunately, she may ask the Eye of Horus some queries. In each query, Ivy chooses two vertices x and
y and a set of vertices S containing neither x nor y. The Eye of Horus tells her whether x and y are
connected after all vertices in S, together with their incident edges, are deleted from the graph. However,
the Eye of Horus has limited computational power, so such a query incurs a cost of max(|S| − 1, 0).
Time is limited. Ivy may make at most 3n2 queries, and the sum of the costs of all queries must not
exceed n⌈log2 n⌉ + 2n. You need to help Ivy devise a strategy that is guaranteed to determine every edge
in the graph.
Recall that an edge cactus is an undirected simple connected graph in which every edge belongs to at
most one simple cycle. A simple graph is a graph with neither multiple edges nor self-loops.
Note that the interactor is adaptive, meaning that the graph for each test case is not pre-determined.
The interactor always guarantees that there is at least one graph consistent with all previous replies, but
it may choose its reply based on your query. The interactor determines the final graph only when you
submit your final answer.

Input
There are multiple test cases. The first line of the input contains an integer T (1 ≤ T ≤ 128) indicating
the number of test cases. For each test case:
The first line contains an integer n (2 ≤ n ≤ 128) indicating the number of vertices in the graph.
It is guaranteed that the sum of n over all test cases does not exceed 256.
The query-count and query-cost limits are evaluated separately for each test case.

Interaction Protocol
To ask a query, output one line. First output ? followed by a space, then print three integers x, y, and
k, followed by k integers s1 , s2 , . . . , sk , all separated by spaces. Here, k = |S|, 1 ≤ x, y ≤ n, x ̸= y,
0 ≤ k ≤ n − 2, and s1 , s2 , . . . , sk must be pairwise distinct and different from both x and y.
After flushing your output, your program should read a single integer t indicating the answer to your
query. If x and y are still connected after deleting S, then t = 1; otherwise, t = 0. Recall that you can ask
