Problem A. Recall
How long must a pushed copy stay?
Treat each push as a separate copy, even when several pushes use the same value. A successful query for
x must refer to the most recent preceding push of x: an older copy cannot survive that push because
simultaneous equal elements are forbidden.
For a push at recorded position i, let needi be the last successful query referring to this copy, or i itself
if there is no such query. Compute these values in one scan. Maintain the latest push position for every
value; initialize needi = i at a push, and at a successful query at position j, set needlastP ush[x] = j. The
existence guarantee ensures that these required lifetimes are consistent with the negative queries.
Greedy reconstruction.
Process the recorded operations from left to right, maintaining a stack of push positions.
• For a push, append + to the answer and push its recorded position.
• For either kind of query, append ?.
• After each recorded operation at position i, repeatedly pop the stack while its top t satisfies
needt ≤ i, appending one - per pop.
An expired copy below a still-required copy must wait: only the top can be popped. When the blocker is
removed, the loop removes all newly exposed expired copies as well. Keeping an active-value array or set
is useful for checking the query results and ensuring that pushes do not create duplicates.
Correctness.
We show that popping an exposed copy immediately after its last required query preserves the existence
of a valid completion. No future successful query needs that copy. Any later successful query for the same
value belongs to a new push, before which the old copy must be removed anyway. Removing it earlier can
only help a negative query or a later push.
More formally, take a valid completion and move this copy’s eventual pop to the present moment.
Operations on copies pushed above it in the completion can still be performed in exactly the same way.
Successful queries for the removed copy do not occur before its next push, and negative queries remain
valid. If it was never popped, deleting it now is also harmless. Thus there remains a valid completion after
every greedy pop.
Starting from the promised valid reconstruction, apply this exchange after each recorded operation. The
next recorded operation must therefore be executable with its stated result. Induction proves that the
entire constructed sequence is valid. All remaining copies expire by the end of the scan; emptying the
stack at that point is allowed, though not required by the problem.
Complexity.
Each pushed copy is pushed and popped once, so the stack processing takes O(n) time and the output
length is at most 2n. With coordinate compression, preprocessing takes O(n log n) time and the total
memory is O(n). A hash table for value states gives expected O(n) total time; this is the approach used
by the model solution.

Problem C. Permutation Inversions
Turn comparisons into a graph.
Create one vertex for each position. For a constraint listing q1 , q2 , . . . , qk in increasing order of values, add
edges q1 → q2 , q2 → q3 , . . . , qk−1 → qk . Consecutive edges imply all comparisons in that constraint, so
only k − 1 edges are needed.
A directed cycle makes the strict comparisons impossible. Otherwise, any topological ordering v1 , . . . , vn
produces a satisfying permutation by setting pvt = t. Notice that we output these assigned ranks by
position, not the topological ordering itself.
Algorithm.
Use Kahn’s topological sorting algorithm, with a min-heap containing all currently zero-indegree vertices.
Repeatedly remove the smallest available position and assign it the next value 1, 2, . . . , n. Delete its
outgoing edges and insert newly available vertices into the heap. If fewer than n vertices are removed,
output −1.
The inversion-minimizing property is special to the interval constraints; the same greedy rule need not
minimize inversions in an arbitrary DAG.
Key lemma.
At any stage, let x be the smallest zero-indegree vertex among the remaining vertices. Every remaining
position y < x is a descendant of x.
To prove this, follow predecessor edges backwards from y until reaching a source z in the remaining DAG.
Such a source exists because the graph is acyclic. We have z ≥ x. If z = x, the claim is immediate.
Otherwise, the path from z > x to y < x either passes through x, or has an edge u → v whose endpoint
indices lie on opposite sides of x.
This edge came from a constraint on a complete interval containing both endpoints, so that constraint also
contains position x. All three positions are comparable in its prescribed total order. Since x is currently a
source, neither remaining endpoint can precede x in that order. Indeed, a path from a remaining vertex
to x cannot go through a previously removed vertex: topological removal never deletes a vertex while an
unremoved predecessor remains. Hence x must precede both endpoints, giving a path from x to v and
then to y. This proves the lemma.
Optimality.
An inversion of p corresponds exactly to an inverted pair in the topological ordering: a larger position x
occurs before a smaller position y precisely when px < py , which makes (y, x) an inversion of p.
When the greedy algorithm removes x, any smaller position y that will appear later is still present. By
the lemma, x reaches y, so every satisfying permutation must place x before y in increasing-value order.

Problem D. Sequence
Key observation.
Construct the binary sequence s from left to right. For the current prefix, only the counts of zeros and
ones matter. Denote them by (a, b), where a counts zeros and b counts ones.
If a > b, complementing every bit does not change any pi , since [si ̸= sj ] is unchanged. By symmetry, we
may keep the state normalized so that a ≤ b.
Case 1: a = b.
Both possible next bits have exactly a opposite bits before them, so both produce the value p = a. We
must consume one occurrence of a from the remaining multiset. If it is absent, construction is impossible.
A remaining value smaller than a also makes construction impossible, since neither count can decrease.
The two choices lead to (a+1, b) and (a, b+1). They give distinct sequences and symmetric continuations,
so the number of choices is multiplied by two.
Case 2: a < b.
If an occurrence of a remains, the next bit must be 1, producing p = a. Choosing 0 instead would increase
the smaller count to a + 1; afterwards both counts would exceed a, so that remaining occurrence could
never be produced.
If no occurrence of a remains, the next bit cannot be 1, so it must be 0, producing p = b. Consume an
occurrence of b; if none exists, there is no valid construction.
Thus the choice is forced whenever a < b. Update the counts after each step and normalize them again if
necessary.
Counting the answer.
Only states with a = b contribute a factor of two. Let their number be k. If all positions can be constructed
while consuming exactly the given multiset, the answer is 2k ; otherwise it is 0. Perform the arithmetic
with the modulus specified in the statement.

Problem F. 50 Years of Excellence
Compute the sum of the m ratings for each year.
Initialize the previous score to 0, which is the defined score immediately before the first year. Process the
years from the first to the last. For each year, increase the answer if the current score is strictly less than

algorithm runs in O(nm) time and uses O(1) additional memory.

First, transform the way we compute score(S, pref (T, x)):
Enumerate each prefix pref (S, i) of S. If it occurs at positions [p−i+1, p] in T with p ≤ x, its contribution

the pattern strings.
Let nodei be the automaton state after matching pref (T, i). Inspecting the nodes inside the subtree of u
in the failure tree is equivalent to inspecting all positions in T where u occurs.
Thus, to compute the answer for a fixed x, we only need to enumerate each node u and compute:

The contribution of u is cntu (sum1 · x + sum2 ).

Problem J. string
Consider the first operation as an example.
If we regard N as 0 and H as 1 (regard left side as lowbit and right side as highbit), performing the operation
k times is equivalent to adding k to the original number.
We can pack every 64 bits into one machine word, similarly to the idea behind a bitset. The operation
can then be performed in O(n/w) time: add the carry produced by the lower word, and then continue
propagating the carry.
For a walk to the right, we can reverse the binary number, perform the operation, and then reverse it
back.
To exchange the meanings of N and H, we only need to take the bitwise complement of the original number,
perform the operation, and then take its bitwise complement again.
The implementation may be somewhat complicated. For example, we need to reverse the bits of a binary
number in O(1) time.
We can preprocess the bit reversals of all 16-bit binary numbers. Suppose four 16-bit blocks a, b, c, d form a
64-bit binary number, and let a′ , b′ , c′ , d′ denote their respective bit reversals. The reversed 64-bit number
is then d′ c′ b′ a′ .
The time complexity is O(nT /w), where w = 64.
Another approach is to handle the lowest log V bits by brute force. For the higher bits, each operation
causes at most one range update and one point update, which can be maintained using a segment tree.
This gives a time complexity of O(n(log n + log V )).

Each value ci is either:

• equal to k minus a constant, if di = R.

• true for every k;
• false for every k;
• true for exactly one value of k.

Correctness proof
Lemma 1. For a fixed total number k, an assignment is valid if and only if there is a path from 0 to
n + 1 using only edges i → i + 1 with ci = ci+1 and edges i → i + 2 with ci+2 = ci + 1.
Proof. Take any valid assignment and list all villagers, including dummy positions 0 and n + 1. Because
no two werewolves are adjacent, consecutive villagers in this list have distance either 1 or 2.
If the distance is 1, no werewolf is between them, so the number of werewolves to the left is the same. If
the distance is 2, exactly one werewolf is between them, so the number increases by 1. Therefore every
consecutive pair gives one of the allowed edges, hence a path exists.
Conversely, given such a path, mark all positions on the path as villagers and all skipped positions as
werewolves. Every gap has length 1 or 2, so no two werewolves are adjacent. The edge conditions guarantee
that every villager’s statement matches the actual number of werewolves on the required side. Hence the
assignment is valid. □
Lemma 2. For a fixed k, the DP recurrence correctly determines whether such a path exists.
Proof. The last edge entering position i can only come from i − 1 or i − 2. The first case is possible
exactly when ci = ci−1 , and the second case is possible exactly when ci = ci−2 + 1. This is exactly the
recurrence. □
Lemma 3. During the sweep over k, all changes of the DP transitions are processed.
Proof. Every transition depends only on an equality between two values among ci−1 , ci , ci+1 . Each such
value is either constant or k minus a constant. Therefore each equality is either always true, always false,
or true for one value of k. The event construction adds updates for precisely these single-value changes,
and the always true/false cases are covered by recomputing the matrix itself. □
Lemma 4. For every value of k, the segment tree product represents the same DP transitions as the
fixed-k recurrence.
Proof. Each leaf matrix is recomputed from the current values of the relevant local conditions. Internal
nodes store boolean products of their children, so by associativity of boolean matrix multiplication, the
root stores the product of all local transitions. This product is exactly the composed DP transition over
the whole row. □
Theorem. The algorithm outputs -1 if and only if no valid assignment exists; otherwise, it outputs a
valid assignment.
Proof. By Lemmas 1 and 2, for each fixed k a valid assignment with exactly k werewolves exists
iff the fixed-k DP succeeds. By Lemmas 3 and 4, the sweep checks this condition correctly for every
k = 0, 1, . . . , n. If no value works, no valid assignment exists. If some value works, the reconstruction runs
the fixed-k DP and, by Lemma 1, produces a valid assignment. □

There are O(n) events. Each event causes O(log n) work in the segment tree, and reconstruction is linear

Structural observations. Sort the strings lexicographically. If two strings share a prefix of length ℓ,
then every string lying between them in sorted order shares that prefix as well, so an optimal group of j
strings can always be taken to be contiguous in sorted order. Hence the common prefix of a group is the
minimum of the adjacent LCPs inside it, and f (i, j) equals the maximum over all windows of j consecutive
sorted strings of the minimum adjacency in the window. Two consequences: f (i, ·) is non-increasing in j
(asking more strings to agree can only shorten the prefix), and it is convenient to work with the transpose
g(i, h), defined as the maximum number of the first i strings that share a common prefix of length h.
The functions f and g are inverse non-increasing staircases: f (i, j) ≥ h if and only if g(i, h) ≥ j, i.e.
f (i, j) = max{h : g(i, h) ≥ j}. This transpose is the key to solving the problem incrementally, because
inserting one string changes g in a very controlled way.
Brute force. For each i, sort the first i strings, compute the adjacency LCP array, and recover every
f (i, j) with a monotone stack (each adjacency is the minimum on a maximal window whose length caps
the group sizes it can serve). Recomputing from scratch each step yields O(n2 ) overall, and a purely
comparison-based version is O(n3 ). This solves the small subtasks and serves as a checker.
Main solution in O(L log n). Maintain an array whose j-th entry equals f (i, j), and grow i from i − 1
to i by inserting si . Consider si together with the already inserted strings, and for each prefix length ℓ

Problem M. Check In
Maintain the registration state.
Store all roster names in a set R, and keep another initially empty set C containing exactly the teams
that have already signed in. Process queries in their input order. For a name s:
• If s ∈
/ R, print WRONG and do not change either set.
• Otherwise, if s ∈ C, print REPEAT.
• Otherwise, print OK and insert s into C.
Names are case-sensitive: do not convert uppercase letters to lowercase or vice versa. In particular,
repeating an invalid name still produces WRONG, not REPEAT.
Correctness.
Before each query, R is exactly the given roster and C is exactly the set of valid teams that successfully
signed in during earlier queries. This holds initially because nobody has signed in. If the queried name
is absent from R, it is invalid. If it belongs to both sets, it has already signed in. Otherwise it is a valid
team signing in for the first time, and inserting it into C preserves the invariant. These are precisely the
three required outcomes, proving correctness by induction.
Complexity.
Let L be the total number of input characters. Using balanced binary search trees, as in the model
solution, the running time is O(L log(n + 1)): each lookup performs O(log(n + 1)) string comparisons,
each bounded by the length of the queried name. Space is O(L).
Alternatively, a hash table mapping each roster name to a signed-in flag gives expected O(L) time and
O(L) space. A trie over the 52-letter alphabet provides a deterministic O(L)-time alternative.

Why only the boundary matters.
There exists an optimal partition in which every non-red segment is a singleton without a red piece: split

Suppose the last segment is red and ends at i. If both of its balances are positive, extend it left through the
preceding segments. A preceding red segment can be merged into it: both balances remain positive and
no previously counted length is lost. A preceding non-red singleton has r = 0, so absorbing it decreases

Add i to each queried maximum and maximize dpi with the results. Every transition constructs a valid

Data structures.
Group all prefix points (Yi , Bi ) by equal Yi . In each group, sort and deduplicate the Bi coordinates and
build a Fenwick tree for prefix maxima. A second family of Fenwick trees groups points by Bi and stores
their Yi coordinates. All coordinates can be prepared offline, but insert the values dpj − j only while
processing prefixes in increasing order.
Initialize every Fenwick entry to negative infinity and insert prefix 0 with value 0. At step i, perform
both queries before inserting prefix i, then update its position in both families with dpi − i. Use an upper
bound for each query so that equality is included. The answer is dpn .
