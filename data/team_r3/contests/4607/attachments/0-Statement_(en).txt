Bouncing Particles

Time limit: 2s

This problem has an attachment. You can use it to simulate and visualize
the movements of the particles.
VegiCat observes particles on a grid with n rows and n columns. The lower-left cell
has coordinates (1, 1). The horizontal coordinate increases from left to right, and
the vertical coordinate increases from bottom to top. Each particle has a horizontal
direction (left or right) and a vertical direction (up or down). At the beginning of
each step, each particle adjusts its directions as follows:

• Its horizontal direction is reversed if the next cell in that direction is outside the grid.
• Its vertical direction is reversed if the next cell in that direction is outside the grid.
After these adjustments, a particle at (x, y) produces two child particles:
• One at (x − 1, y) if its horizontal direction is left, or at (x + 1, y) if it is right;
• One at (x, y − 1) if its vertical direction is down, or at (x, y + 1) if it is up.
Both child particles inherit the parent’s horizontal and vertical directions. The parent then disappears.
Multiple particles may occupy the same cell at the same time, regardless of their directions. They do not
interact or change each other’s directions.
At time 0, there are four particles at (x0 , y0 ), with the following direction pairs:
• Right and up;
• Left and up;
• Right and down;
• Left and down.
At each step, all particles simultaneously adjust their directions and then split as described above.
You are given q queries. Each query gives integers A, B, C and a time t. For each query, ﬁnd the number of
grid cells (x, y) that satisfy Ax + By + C = 0 and contain at least one particle at time t.

Input
The ﬁrst line contains an integer T (1 ≤ T ≤ 105 ), the number of test cases. The description of the test cases
follows.
The ﬁrst line of each test case contains four integers n, x0 , y0 , q (2 ≤ n ≤ 109 , 1 ≤ x0 , y0 ≤ n, 1 ≤ q ≤ 105 ). The
grid has n rows and n columns. The initial cell is (x0 , y0 ), and there are q queries.
Each of the next q lines contains four integers A, B, C and t (|A|, |B|, |C| ≤ 109 , 0 ≤ t ≤ 109 ). This describes a
query for the line Ax + By + C = 0 at time t. It is guaranteed that A and B are not both 0 simultaneously.
It is guaranteed that the sum of q over all test cases does not exceed 105 .

Output
For each query, output one integer on one line: the number of grid cells (x, y) that satisfy Ax + By + C = 0
and contain at least one particle at time t.

Duel of Wrath

Time limit: 1s

VegiCat and VegiDog are playing a special duel in Slay the Spire. VegiCat plays as
Watcher A, and VegiDog plays as Watcher B. A and B have base attack powers a and
b and initial health values hA and hB , respectively.
At the start of each round, the game determines each Watcher’s stance for that round.
Each Watcher can be in one of the following two stances:
• Normal: damage dealt and damage received are unchanged.
• Wrath: damage dealt and damage received are both doubled.
For each attack, the damage initially equals the attacker’s base attack power. It is
doubled if the attacker is in Wrath and doubled again if the defender is in Wrath.
Thus, the damage in each round is as follows:
• If both characters are in Normal, A deals a damage to B, and B deals b damage to A.
• If exactly one character is in Wrath, A deals 2a damage to B, and B deals 2b damage to A.
• If both characters are in Wrath, A deals 4a damage to B, and B deals 4b damage to A.
Each round, both characters attack once simultaneously, and both health values decrease simultaneously. Both
attacks take eﬀect even if either character’s health becomes 0 or less during the round. At the end of the
round, a character with health less than or equal to 0 dies. If either character dies, the battle ends immediately;
otherwise, the next round begins. Base attack powers never change, and health is never restored.
The stances for each round are determined by the game, not by the players. Any combination of the two
characters’ stances is possible in each round.
VegiCat wins only if B dies while A remains alive. If both characters die in the same round, VegiCat does not
win. Determine whether VegiCat will win regardless of how both characters’ stances change.

Input

follows.
Each test case contains one line with four integers a, b, hA , and hB (1 ≤ a, b, hA , hB ≤ 1018 ), giving the
characters’ base attack powers and initial health values, respectively.

Output
For each test case, output YES if VegiCat will win regardless of how both characters’ stances change, and NO
otherwise. Output each answer on a separate line.
You can output the answer in any case. For example, yEs, yes, Yes, and YES are all accepted as positive

Enclose the Point

Time limit: 1s

There are n points P1 , P2 , . . . , Pn in the plane. VegiCat has q queries for you. Each
query gives a point P .
For each query, construct a simple polygon using some of the given points as its
vertices. The polygon must contain P strictly inside it and have the minimum
number of vertices. If no such polygon exists, output −1.
A simple polygon is a closed polygonal chain with at least three distinct vertices.
Adjacent edges intersect only at their common endpoint, and nonadjacent edges do
not intersect.

Examples of simple and non-simple polygons

Input
The ﬁrst line contains an integer T (1 ≤ T ≤ 2 · 104 ), the number of test cases. The description of the test cases
follows.
The ﬁrst line of each test case contains two positive integers n and q (3 ≤ n ≤ 105 , 1 ≤ q ≤ 105 ), representing
the number of given points and the number of queries.
The i-th of the next n lines contains two integers xi and yi (−109 ≤ xi , yi ≤ 109 ), the coordinates of Pi . It is
guaranteed that these n points are pairwise distinct.
Each of the next q lines contains two integers x and y (−109 ≤ x, y ≤ 109 ), the coordinates of the queried point.
It is guaranteed that the sum of n over all test cases does not exceed 105 .
It is guaranteed that the sum of q over all test cases does not exceed 105 .

Output
For each query, if no polygon satisfying the requirements exists, output one integer −1 on a line.
Otherwise, output a polygon with the minimum number of vertices. On the ﬁrst line, output one integer m,
the number of vertices.
On the second line, output m integers a1 , a2 , . . . , am (1 ≤ ai ≤ n), the indices of the vertices in order. The
polygon is Pa1 Pa2 . . . Pam . The vertices may be output in either clockwise or counterclockwise order.
The indices must be pairwise distinct, and the output polygon must be simple and contain the queried point
strictly inside it. If there are multiple solutions, output any of them.

word, even if they occur at diﬀerent positions in S.

qwertyuiopasdfghjklzxcvbnm deﬁnes the following mapping:

Hidden Order

Time limit: 1s

This is an interactive problem.
VegiCat knows an array a1 , a2 , . . . , an , where each element is 0, 1, or 2. He does not
want to tell you its values, but you can ask him questions. In each query, you choose
two indices i and j, and VegiCat tells you whether ai > aj .
VegiCat asks you to output the indices in nondecreasing order of the corresponding
array values. That is, ﬁnd a permutation p1 , p2 , . . . , pn of 1, 2, . . . , n such that
ap1 ≤ ap2 ≤ · · · ≤ apn .
You may make at most 2n − 3 queries in each test case.
The interactor is adaptive. This means that the array is not ﬁxed in advance. The interactor guarantees
that there always exists at least one array with elements in {0, 1, 2} consistent with all responses given so far.
Your ﬁnal permutation must be valid for every array consistent with all responses.

Input
The ﬁrst line contains an integer T (1 ≤ T ≤ 250), the number of test cases. The description of the test cases
follows.
Each test case begins with an integer n (2 ≤ n ≤ 500), the length of the array.
The sum of n over all test cases does not exceed 500.

Interaction
To make a query, output a line in the following format:
? i j
Here, 1 ≤ i, j ≤ n. After each query, read one integer:
• 1, if ai > aj ;
• 0, if ai ≤ aj .
Queries with i = j and repeated queries are allowed and are included in the query count.
When you have determined the order, output a line in the following format:
! p_1 p_2 ... p_n
Each index from 1 to n must appear exactly once. Printing the answer does not count as a query.
If your answer is correct, proceed to the next test case by reading its n, or terminate your program if this was
the last test case. The interactor does not send a separate conﬁrmation after an answer.
After outputting each query or answer, output a newline and ﬂush the output buﬀer. To ﬂush your output, you
can use:
• fflush(stdout) or cout.flush() in C/C++;
• System.out.flush() in Java and Kotlin;
• sys.stdout.flush() in Python.
If you make an invalid query, exceed the query limit, or print an incorrect answer, you will receive a Wrong
Answer verdict. Output that does not follow the speciﬁed format is also judged Wrong Answer. In these
cases, the interactor terminates without sending an error response.

Invisible Edges

Time limit: 1s

This is a multi-pass problem.
VegiCat and VegiDog play a game with a forest of n vertices, numbered from 1 to n,
and m edges. A forest is an undirected graph with no cycles. It is not necessarily
connected.
In the ﬁrst stage, VegiCat assigns an integer au (1 ≤ au ≤ 2n) to each vertex u. The
values may repeat.
After VegiCat ﬁnishes assigning the values, the vertices are renumbered. Let
p1 , p2 , . . . , pn be a permutation of 1, 2, . . . , n, in which each integer from 1 to n appears
exactly once. For each u, the vertex originally numbered u is now numbered pu .
Each edge (u, v) becomes (pu , pv ). Each vertex keeps its assigned value. Let bi be the value at vertex i after
renumbering. Then bpu = au .
In the second stage, VegiDog receives only n and b1 , b2 , . . . , bn , without the original forest or p. He must recover
all edges using the new vertex numbers.
Design strategies for both players that work for every valid forest and every permutation p.

Input
Your program will run twice: ﬁrst as VegiCat, then as VegiDog. The test cases appear in the same order in
both runs.
First Run. The ﬁrst line contains the string cat, indicating that you play VegiCat.
The second line contains an integer T (1 ≤ T ≤ 104 ), the number of test cases. The description of the test cases
follows.
The ﬁrst line of each test case contains two integers n and m (1 ≤ n ≤ 2 · 105 , 0 ≤ m < n), the number of
vertices and edges.
Each of the next m lines contains two integers u and v (1 ≤ u, v ≤ n, u ̸= v), describing an undirected edge
between vertices u and v.
It is guaranteed that the graph has no cycles or multiple edges.
It is guaranteed that the sum of n over all test cases does not exceed 2 · 105 .
Second Run. The ﬁrst line contains the string dog, indicating that you play VegiDog.
The second line contains an integer T (1 ≤ T ≤ 104 ), the number of test cases. The description of the test cases
follows.
The ﬁrst line of each test case contains an integer n (1 ≤ n ≤ 2 · 105 ), the number of vertices.
The second line contains n integers b1 , b2 , . . . , bn (1 ≤ bi ≤ 2n), the assigned values in the new vertex order.
It is guaranteed that the sum of n over all test cases does not exceed 2 · 105 .

Output
First Run. For each test case, output n integers a1 , a2 , . . . , an (1 ≤ ai ≤ 2n) on one line. The integer ai is the
value assigned to vertex i.
Second Run. For each test case, output an integer m on the ﬁrst line, the number of edges. Each of the
next m lines must contain two integers u and v (1 ≤ u, v ≤ n, u ̸= v), describing an edge using the new vertex
numbers.
Output each edge once, in any order. Either endpoint may come ﬁrst. If m = 0, output only 0.
