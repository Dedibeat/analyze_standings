### C. Jiaxun! — field 1396 — **AC 99.7' after 3 WA**
- **Idea:** maximise the minimum load. By Hall's theorem the answer is
  min(⌊S/3⌋, each student's reachable total, ⌊(S − F_only_other)/2⌋ for each pair). Alternatively,
  binary search with a correct greedy or flow check. Tags: Hall's theorem, binary search.
- **Attempts:**
  1. 2914380 (25.9') WA: ad-hoc pairwise balancing in a fixed order (F3 between 1 and 2, then F6,
     then F5, then F7 to the minimum). A **greedy without proof**.
  2. 2914450 (32.4') WA: a typo fix (`f[7] -= (c / a) * 2` → `(c - a) * 2`) in the same wrong
     greedy.
  3. 2914780 (57.4') WA: binary search on the answer, but the feasibility check is a fixed-order
     greedy (student 1 takes F3 before F5 before F7, …), which is not a valid check.
  4. 2915376 (99.7') AC: six lines of Hall-type bounds
     (`ans = min(s / 3, f1+f3+f5+f7, …, (s - f[1]) / 2, …)`).
- **Lesson:** for "assign items to people who can take them" think **Hall's theorem / max-flow
  bounds** before writing a greedy. Three WAs came from unproven allocation orders.

### D. Arcane Behemoths — field 1598 — **AC 106.2', first try**

### E. Zero — field 892 — **AC 187.7', first try**
- Inclusion–exclusion on adjacent-equal pairs, using "pairs are uniform in [0, 2^m)". Closed form
  with fast powers. Clean.

### H. Tree Shuffling — field 611 — **AC 155.7', first try**
- Count resulting sequences by the shortest chain that realises them: for each chain length L,
  (L! − 2(L−1)! + (L−2)!) times the number of chains of that length, plus the identity. O(n²).

### I. DAG Query — field 417 — **not attempted; the 6th problem**
- **Idea:** f(1, n, c) is a polynomial in c of degree ≤ n−1. Query it at n−1 points (f(1, n, 0) = 0)
  and use Lagrange interpolation to get f(1, n, k). Tags: interactive, polynomial interpolation.
- A **known trick** (interpolation) wrapped in an interactive statement. **Library gap?** Lagrange
  interpolation at arbitrary points: do we have it?

### J. Reconstruct the tree — field 190 — **AC 243.7' after TL, WA**
- **Idea:** the pairs must form a complete multipartite structure (groups with all cross edges);
  the vertices outside every pair are "special". Diameter 2 or 3 constructions, or a chain of special
  vertices with groups hanging off it. Verify by hashing neighbourhoods. Tags: constructive, hashing.
- **Attempts:**
  1. 2917141 (227.0') TL: `map<int, vector<int>> mp` keyed by neighbourhood hash, then iterated as
     `for(int i = 0; i < sz(mp); i++) for(auto j : mp[i])`. `mp[i]` **inserts** new keys, so
     `sz(mp)` grows forever.
  2. 2917247 (238.2') WA: hashes compressed to indices `0..l-1` (TL fixed), but in the two-group
     case the two special centres `x[0]`, `x[1]` are never joined, so the tree is disconnected.
  3. 2917302 (243.7') AC: `cout << x[0] << " " << x[1] << "\n";`.
- **Lessons:** `map::operator[]` inserts; iterate maps with iterators. For constructive output,
  check the printed graph is a tree (n−1 edges, connected) with a 10-line validator.
