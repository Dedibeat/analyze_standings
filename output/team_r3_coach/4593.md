### C. Cryptarithm — field 270/402 — **AC 132.7' after 1 WA** (Dedi)
- **Idea:** DP over b's index with state "which element of a (cyclic, at most one wrap = one extra
  paste) produced b_i". The transition k → r costs (r−k−1)·z deletions + |a_r − b_i|·y
  (+ x on a wrap). The k-dependent part is linear (−k·z), so the best k is a **prefix minimum of
  dp[k] − k·z**: O(nm) total. Tags: DP, prefix-min optimization.
- **Ours:** DP plus divide-and-conquer optimization (`comp(l, r, lo, hi, i)`), O(nm log n). Correct
  but heavier than needed: the plain prefix minimum is about 5 lines.
- **Attempts:**
  1. 3275000 (112.8') WA: `const int ... inf = 1e18;`. The answer can reach
     m·|a−b|·y ≈ 3000·10^9·10^6 = 3·10^18 > 10^18, so "infinity" was smaller than real values.
  2. 3275321 (132.7') AC: `inf = (int)4e18` and everything switched to `unsigned long long`, plus
     a brute force and a random tester. The `uint` rewrite was not needed, but it hid the real fix.
  3. 3276249 (190.3') AC again with signed ints and `inf = 4e18`, i.e. confirming in contest that
     `inf` alone was the bug.
- **Bug class:** sentinel/overflow (the infinity was too small for the answer's range).

### H. Hydra — field 155/402 — **AC 168.2', first try** (Erdene)
- **Idea (from our code):** with metallization fixed at M, the optimal plating is the greedy "keep
  the decayed level, buy up to max(0, b−M) when short". Our code runs the plating-only greedy once
  and records each purchase as an interval (cur, b]. Raising M by one inside an interval saves y.
  The total cost is piecewise linear in M, so one event sweep gives the minimum. Tags: greedy,
  piecewise-linear sweep.
- **Ours:** 3275892, 1.1 KB, first try. A good, compact solution.

### J. Journey — field 302/402 — **AC 153.0' after 1 RE** (Dedi)
- **Idea (from our code):** union each value's two occurrences, then scan with a stack: push when
  the current index is in the same component as the stack top, otherwise match it with the top
  (emit ')') and union the two components. The cycle stays a single component. Tags: constructive,
  DSU, bracket stack.
- **Attempts:**
  1. 3274161 (57.8') RE: `const int N = 2e5 + 5; int f[N];` while the DSU is indexed up to
     2n = 4·10^5. The algorithm was correct.
  2. 3275662 (153.0') AC: `N = 4e5 + 5`. It also added a random tester (`test(5, 1000000)`) and a
     `cnt != n - 1` self-check, i.e. the 95 minutes were spent suspecting the algorithm.
  3. 3275839 (165.2') AC: the original 57.8' code with only `N = 4e5 + 5`, proving the RE was
     only the array size.
- **Lesson:** on RE, first compare every array size with the largest index used (here 2n, not n).
  That check takes a minute. Here the RE cost 95 minutes on the second-easiest problem.

## Takeaways from this contest
1. **Pure speed on four easy-to-medium problems; we were 1.3–2.2× slower on each.** This set
   rewarded fast, clean implementation, not ideas.
2. **RE debugging was the costliest item.** The array was sized n instead of 2n. 95 minutes passed
   between the RE and the AC, partly spent stress-testing a correct algorithm.
3. **Sentinel too small** (inf = 1e18 with answers up to 3·10^18): the same family as Chengdu's
   overflow (4607 D).
4. **Load imbalance:** one member held two of the four problems and both stalled. No recorded
   contribution from Tamir.
5. **Resubmitting after AC** (twice) cost time.
6. **Nothing submitted after 190'.** The gold-making 5th problem (G or L) went unattempted as far as
   the data shows.
