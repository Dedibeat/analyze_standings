## Problems

### A. Tower — field 257 (QOJ) — **AC 228.0' after 2 WA** (idea Tamir, implementation Dedi)
- **Idea:** halving first and then ±1 is never worse. The final common value is the median of the
  chosen (halved) numbers, so it is some a_i / 2^k: O(n log V) candidates. For each candidate, cost
  each tower (halve while it helps, then ±) and take the m cheapest. O(n² log V). Tags: greedy,
  candidate enumeration.
- **Attempts:**
  1. 3130459 (128.0') WA, **wrong greedy**: repeatedly halve the currently largest tower and
     evaluate the sorted-window median cost after each step (`priority_queue … a[i] /= 2`). Halving
     decisions depend on the target, so a global "halve the largest" order is wrong.
  2. 3130682 (156.6') WA, **unproven unimodality**: a correct per-target cost `f(x, y)`, but the
     target is found by binary search on `comp(mid) > comp(mid + 1)`, assuming the cost is
     unimodal in the target. The commented-out probes (`comp(i) - comp(i+1) < comp(i+1) - comp(i+2)`)
     in the AC show it was then checked and is not.
  3. 3131303 (228.0') AC: tries every `x, x/2, x/4, …` of every a_i as the target. This is the
     editorial's method.
- **Check** (all 1248 cases with n ≤ 3 and heights ≤ 12 against a brute force): run 1 fails 42,
  run 2 fails 372, the AC fails 0.
- **Lesson:** both WAs submitted an assumption that a 10-line brute force over small arrays would
  have refuted. Search over the answer (binary or ternary search) needs a monotonicity or convexity
  argument first. If you cannot prove it, check it by brute force before submitting.

### C. DFS Order 2 — field 68 (QOJ) — **failed: WA, TL** (Dedi)
- **Idea:** the position of v depends only on the order of siblings along the root path. For each
  node build one knapsack over all children (count, total size), then for each child **remove** that
  child's item from the knapsack (0/1 knapsack undo) instead of rebuilding it. O(n³) total.
  Tags: tree DP, knapsack with deletion.
- **Attempts:**
  1. 3131165 (213.3') WA: `comb(n + 1), combup(n + 1)` default to 0 instead of 1, and
     `int c = comb[u] * combup[u];` has no `% mod` (overflow). UBSan on a 92-node tree reports
     `signed integer overflow: 720 * 172540857379968000` at line 101.
  2. 3131402 (236.2') TL: those fixed. But for each child `v` it rebuilds the knapsack over all
     other children (`for(int v : ch) … for(int w : ch) if(v == w) continue; …`). That is
     O(n · deg³), O(n⁴) on a star with n = 500.
- **Lesson:** the "remove one item from a 0/1 knapsack" trick (or prefix/suffix knapsacks) is a
  library-level technique. It was the 6th problem and silver-to-near-gold here (#92 → #48).

### E. Identical Parity — field 460 (QOJ) — **AC 57.6' after 1 RE** (Dedi)
- **Idea:** positions i and i+k share parity, giving k groups of sizes ⌈n/k⌉ and ⌊n/k⌋. Decide
  whether ⌈n/2⌉ odd numbers fit as a sum of whole groups: a small linear Diophantine range check.
  Tags: math.
- 3129901 (53.3') RE: `int d = (a / B);` with `B = A - 1 = 0` when n = k → **division by zero**.
  3129936 adds `if(n == k)` and `if(k == 1)` special cases → AC 4 minutes later.
  UBSan on input `1 1` confirms: `3129901.txt:26:20: runtime error: division by zero`.
- **Lesson:** every division needs "can the divisor be 0?". k = n is the first edge case to try.
