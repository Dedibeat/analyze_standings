### D. Transitivity — field 1607 — **AC 64.2' after MLE, MLE, WA**
- **Idea:** each component must become a clique; add C(size,2) − edges per component. If every
  component is already a clique, merge the two smallest: size1·size2. Tags: DSU/BFS, counting.
- **Attempts:**
  1. 2791764 (33.4') MLE: recursive DFS (depth up to 10^6) plus a `set<int> st` of edge ids per
     component, in **128 MB**.
  2. 2791776 (39.3') MLE: DFS moved to a global function and `#define int long long` added, which
     makes memory worse.
  3. 2791802 (54.0') WA: an iterative BFS with `vector<char>` flags (memory fixed), but the start
     vertex is never marked visited, so it is counted twice.
  4. 2791814 (64.2') AC: `vis[i] = 1;` for the start.
- **Lesson:** with n, m = 10^6 and 128 MB, budget memory before coding (adjacency ≈ 2m pairs ≈
  16 MB, no `set` per component, no deep recursion). `#define int long long` doubles every array.

### G. Spanning Tree — field 582 — **AC 217.6' after 5 MLE**
- **Idea:** process the operations with a Kruskal reconstruction tree. Each operation contributes
  1/(|A|·|B|), and the given tree is achievable iff every target edge's endpoints have a distinct
  "merge node" (LCA in the reconstruction tree), each used exactly once. Tags: DSU, Kruskal tree,
  LCA, probability.
- **Attempts:**
  1. 2791812 (63.2') MLE: small-to-large sets of incident target edges, but DSU `find` is
     **`return dsu[u] = get(u);`**: infinite recursion → stack overflow, reported as MLE.
  2. 2791818 (66.5') MLE: adds `st[v].clear()`. The recursion bug remains.
  3. 2792255 (199.3') MLE: a new Kruskal-tree + LCA approach (`get` fixed to `get(dsu[u])`), with
     `int up[22][2e6]`, i.e. **176 MB** of lifting table plus 2·10^6 adjacency vectors, recursive DFS.
  4. 2792271 (203.2') MLE: iterative DFS. Still the table.
  5. 2792287 (209.1') MLE: removes the `inv` array. Still the table.
  6. 2792327 (217.6') AC: replaces binary lifting with O(n)-memory jump pointers (161 MB used).
- **Lessons:** (1) a typo in DSU find cost two runs: **the DSU must come from the library**, not be
  retyped. (2) Memory estimation: 22 × 2·10^6 × 4 B = 176 MB was predictable before submitting.

### I. Pa?sWorD — field 694 — **AC 160.2' after 1 TL**
- **Idea:** DP over (last character, mask of {upper, lower, digit} seen). For '?', use "total minus
  same character" to avoid the 62×62 transition. **32 MB** memory: rolling arrays.
- 2792065 (152.9') TL: transitions loop over 62 previous × 62 next × 8 masks per position
  (≈ 3·10^9). 2792090 (160.2') uses the column sum minus the same character → AC.
- **Lesson:** count operations before submitting (n·62²·8 at n = 10^5).

### K. Minimum Euclidean Distance — field 309 — not attempted; **the 7th problem**
- E|P − X|² over a uniform disk = |P − center|² + r²/2. So minimise the squared distance from the
  centre to the convex polygon (inside → 0; otherwise the nearest edge, via binary search or O(n)
  per query with n, q ≤ 5000). Tags: geometry, expectation. **Needs a reliable point-to-polygon
  distance routine** (library gap).

## Takeaways from this contest
1. **Memory limits were not read or budgeted**: six MLEs in one contest (deep recursion, sets per
   component, `long long` everywhere, a 176 MB lifting table).
2. **A retyped DSU with a typo** (`get(u)`): a library item.
3. **Complexity not estimated** (I's TL).
4. Misread constraint on the easiest problem (L: k ≥ 2).
5. This was the first virtual of the season. Several of these classes (memory, misreading
   constants) reappear later (e.g. 2575 J memory, 4607 C modulus).
